# 临床资产研究页 UI 迭代验收

本轮仅调整 `/assets` 的只读页面与页面测试。没有更改归并逻辑、采集工作、来源原件、生产数据库或服务配置；共享导航与样式由主任务接入。

## 研究路径

1. 公司入口保留按公司名称、证券代码和已存申办方搜索，以及每页 18 家的入口分页。
2. 进入公司后先看到当前已存去重 NCT 数、最近查询尝试与日期、当前采集队列。失败原因独立折叠，采集任务入口指向 `/coverage#collection-queue`。
3. 名称列表支持关键词、用药角色、实际来源的试验阶段原文、批次可见性，以及名称或关联试验数排序。阶段仅做原文精确匹配；名称卡保留该名称的全部试验来源，不推断最高研发阶段。
4. 角色快捷入口显示当前其他条件下的真实名称数。筛选反馈可逐项移除，角色切换和筛选移除从名称第一页开始；保留同公司与原公司目录搜索/分页上下文。
5. 名称结果维持每页 50 项。卡片外层与每项试验均用原生 `details` 折叠，展开仍可核对完整原文、SHA-256、批次和日期。每项 NCT 同时提供公司范围的本地已存观察入口，并明确外部链接打开的是可能已更新的当前登记页面。

## 状态和证据边界

- 已存 NCT 数、最近查询结果数和名称数分别呈现。名称数量不等同于独立药物资产数，登记角色不构成药物权益证据。
- 有名称但条件未命中时显示“当前筛选无匹配”，可清除当前公司的筛选；没有名称时提示采集、来源结果和干预类型的范围限制。两者都不能据此判断公司没有研发管线。
- 查询失败、不完整、缺失批次或无法判定时间先后的记录均不显示为完整零结果。
- 页面明确完整性未在此页重新校验、科学审查尚未在此页判定、人工签署及药物权益需另行核对。界面测试通过不构成科研或临床验证。
- 页面无脚本、无内联样式，全部用户输入及来源文本转义；外部来源链接仍只允许与 NCT 匹配的官方登记地址。
