# 临床资产研究入口可用性迭代

本轮仅修改 `market_asset_view.py`、对应 UI 测试和本文档。未修改生产数据库、调度、采集器或共享 shell，未下载研究数据，也未重启或提交代码。

## 默认入口

`/assets` 现在直接展示已配置公司的可点击入口，以公司名称、证券代码和已存申办方名称进行本地搜索。搜索参数为 `company_q`，按字面匹配并忽略大小写，不把 `%` 或 `_` 当作通配符。

公司入口每页最多 18 项，参数为 `company_offset`。偏移量按页大小对齐并限制到实际结果最后一页；缺失、非法或负数回到第一页。选中公司时保留搜索与页码上下文，资产页可返回原公司列表。原有公司选择和药物筛选表单保留在默认折叠区内。

入口卡片分别展示当前已存的去重 NCT 数量、最近登记查询尝试及其开始或完成时间；已有活跃公司采集任务时另列队列状态。可以直接进入 `/coverage#collection-queue` 查看采集任务与错误。

## 数量与证据边界

已存数量来自当前 `trials` 表，以公司和 NCT 范围计数。最近查询尝试来自 `ClinicalTrials.gov` 的运行记录；来源时间、当前已存数量及任务状态彼此独立，不能替代完整管线核验。

- 无查询记录时，结果数量保留未知；已存零项不被表述为来源查询零条。
- 最近尝试失败、分页未完成、中断或取消时，明确说明本次结果范围未确认。
- 仅当成功查询记录明确保存返回数量零时，报告该来源范围的零结果。
- 新查询返回零条时，仍保留并显示既有历史登记，不能据此推定项目终止。
- 查询时间缺失、无时区、无法解析或明显在未来时，不推断最近尝试的先后，保留待核实。
- 名称数、登记试验数和公司入口数量均不等于独立资产数，不产生药物权益或临床成功概率。

## 进入公司后

页头明确当前公司与代码，并提供固定的同公司入口：`/market?company=…` 和 `/disclosures?company=…`。已核对这两个页面接受 `company` 参数；未配置披露来源的公司会进入对应缺口状态。

原有名称、试验和适应症搜索、角色筛选、证据与 50 项名称分页保留。资产偏移量同样按 50 对齐，避免 `offset=1` 或 `49` 造成前后页重叠。

每个名称仍可展开全部试验依据，且每项试验再使用独立、默认折叠的原生 `details`。摘要显示 NCT、原文状态和阶段短预览；展开后保留完整标题、角色、阶段、适应症、日期、来源链接、批次与 SHA-256。来源条目不截断或删除。

## 验证状态

聚焦测试为 `tests/test_market_asset_view.py` 和 `tests/test_market_assets.py`，共 **51 passed，0.88 秒**。其中包括 22 项新增的参数化 UI 用例，验证公司搜索和分页边界、返回上下文、同公司路由、准确数量、失败与零结果区别、未知时间、采集队列独立状态、HTML 转义和逐试验折叠。既有资产证据与只读渲染回归同时通过。

实现仅使用服务端 HTML 和原生表单、链接、`details`，没有 JavaScript、内联事件或外部资源依赖。浏览器视觉验收与 runtime 同步由主 agent 执行，本轮测试结果不等于实际浏览器验收完成。
