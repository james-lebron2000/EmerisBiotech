# 临床资产研究工作台本地发布验收

2026-10-18（UTC+8）。用户要求设置 subagent 优化工作台 UI。本轮由页面实现、独立审查、服务与并发修复三个 subagent 协作，主任务负责共享界面、集成、受管服务发布与浏览器实机检查。

## 可用流程

- 首页主操作进入 `/assets` 公司入口；按公司名称、证券代码或已存申办方查询。
- 公司研究页显示已存去重 NCT、最近查询尝试及时间、当前队列；失败原因和未核实状态单独呈现。
- 关键词、用药角色、阶段原文、批次可见性与排序可以组合。角色快捷入口显示其他筛选条件下的计数，移除单一条件后保留公司和其余条件，翻页保留条件。
- 名称卡片逐层展开到每项试验、原文角色、来源日期、本地观测时间、批次和 SHA-256。每项 NCT 提供同公司本地观察入口，外部当前页面单独标明。
- 历史表格显示保存的分析开始/结束或循环创建时间，统一为 UTC+8。缺字段、无时区、无效或时间矛盾均保留未知，不根据 ID 或文件修改时间推算。
- 窄屏使用单列名称卡、两列指标和可换行筛选条件；触屏主要控件使用至少 44px 点击区域。

名称数量、去重试验数和完整管线分开。阶段保留来源原文，不推断药物最高研发阶段；当前页不将采集成功或可见校验值升级为科学审查、人工签署或药物权益。

## 运行与恢复

本轮发布只更新五个运行模块（共享 shell、首页、历史、资产页和市场查询），逐文件核对运行目录与源码 SHA。既有其他开发中的后端改动未混入本次运行版本。

发布前确认 launchd 加载参数、工作目录和受管实例一致，停止该实例，使用 SQLite backup API 备份四个状态库并检查市场库 `quick_check=ok`。市场库从 DELETE journal 切换为 WAL，以支持本地页面与采集并发读取。旧模块、配置和状态库保存在本机应用数据目录的 `backups/ui-research-<UTC timestamp>/`，部署记录保存具体位置和前后校验值。初次停止后曾遇到 launchd 异步退出，先确认实例已卸载，再完成发布和重新加载；未覆盖未知服务或删除数据库。

受管服务状态必须同时核对加载配置、唯一 PID、端口实际监听 PID 与正确应用响应；单独端口响应不足以报告该服务就绪。详见 [本地服务说明](LOCAL_MANAGED_SERVICE_2026-10-18.md)。恢复需先停止已核实的受管实例，保留当前状态备份，再恢复选定历史模块和一致状态库，随后重新校验与启动；不能在运行中直接覆盖活动 SQLite 文件。

本轮没有下载研究数据、发布公网服务、创建客户账号、重建云端镜像或升级任何科学结论。云端与客户生产验收仍需单独完成。
