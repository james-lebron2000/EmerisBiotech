# 工作台可用性验收 — 2026-10-17

本轮安排两个 UI 子任务：一项负责资产入口实现，另一项独立审查；主任务整合历史记录、导航与响应式样式，并验收实际本地浏览器。工作台继续采用深蓝／青绿风格和原生 HTML 控件，不增加 JavaScript、外部字体或模型依赖。

## 可以使用的流程

1. 在 `/assets` 按公司名、证券代码或已存申办方字面搜索。公司入口每页 18 项，分别展示已存 NCT 数量、最近登记查询状态与日期、活跃采集任务。失败、零结果、缺失记录及未完成查询分别说明，不能解释为公司没有管线。
2. 进入公司后筛选用药名称、NCT 或适应症及用药角色。同公司登记记录、官方披露与缺口均有直接入口，返回公司目录时保留搜索与页码。
3. 展开名称卡片，再逐项展开试验。试验摘要展示 NCT、状态和阶段原文；完整登记字段、原件链接、观测时间、批次及 SHA-256 均保留，没有截断来源。
4. 在 `/records` 分别筛选记录类型、执行状态、科学审查和合成测试标记，匹配结果每页 20 条。详情的返回链接保留关键词、条件和页码，且只接受经过校验的本地历史路径。
5. 手机端历史表格按记录显示为卡片，仍保留表格语义和逐字段标签。`/jobs` 明确命名为“完整性校验”，另链接覆盖页的市场采集任务。

只有原始明确记录的 `pending` 才显示为待科学审查；缺失、空值或 `None` 保留未知。合成筛选使用已有标题标记，未标记的记录不因此成为已验证的临床研究。
