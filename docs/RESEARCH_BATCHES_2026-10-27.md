# 本地研究任务批次、预算与恢复

对应 [Issue #30](https://github.com/james-lebron2000/EmerisBiotech/issues/30)。首轮只编排 `audit_bound_sources` 与 `extract_interaction_evidence` 两项主机只读工具。当前 UC 草案里的人工研究任务仍需实际研究者落实。

## 操作流程

1. 从当前、未过期的草案中勾选工具任务，记录依赖、最大尝试次数、总执行窗口、单次时限与实际记录人。
2. 保存批次仅追加记录。选择运行后，主机依次执行满足依赖的任务；任一失败、取消、上下文变化或预算耗尽会停止后续派发。
3. 已完成任务不重复执行；旧的单任务按钮也进入同一队列。失败后需要记录理由、显式重试，并继续使用原批次预算。
4. 请求存在但缺少回执时保持未知。先核查原控制进程和子进程已释放执行锁，再显式登记中断状态；恢复本身不重跑工具。

入口：`/programs?id=osmr-uc-independent#research-batches`。可导出批次、依赖、每次请求与完成／未知状态 JSON。

## 预算与状态

任务集固定为 1–8 项。最多派发 1–32 次，包含失败和显式重试；总执行窗口为 1–600 秒，单次时限为 1–120 秒。首次派发开始窗口计时，未开始的排队等待不消耗该窗口。

每次派发先预留不超过剩余窗口和单次上限的秒数。工具完成后记实测耗时；未知结果保留 `elapsed_seconds=null`，按整份预留额度计入预算，不能当作零耗时。后续派发同时受累计计入额度、首次派发后的墙钟窗口与尝试次数限制。进程清理、数据库和回执处理存在额外开销，不保证整个 HTTP 请求在这个秒数内结束；窗口结束后不再派发新任务。

批次状态分别表达可执行、等待依赖、存在未完成请求、需要处理失败、预算耗尽、取消、过期和全部工具完成。任务未派发与已派发但没有结果分别记录。全部工具完成仍为待科学审阅，不改变证据、验证计划、实验结果、研发或 BD 决定。

本轮控制的是本地只读工具时间与次数。计算费用没有计量，金额保持 null；不将秒数换成实际费用或将未知成本填成零。模型服务的 token／美元总预算、湿实验预算与项目组合资源分配仍需后续实现。

同一批次的预算不能静默增加。预算耗尽后的追加额度审批尚未实现；不得借重复提交或改变依赖给同一个任务重置预算。当前只能为新的、明确版本化研究意图建立后续任务，保留旧历史。

## 去重与并发

批次身份绑定项目、packet、草案事件、任务集和依赖。任务键另绑定任务 ID 与主机工具；packet 已包含登记来源版本。同一批次重复提交读回已有记录，预算不同则拒绝；同一任务不能进入另一个批次以绕过原额度。

派发资格和请求写入使用同一项目历史版本做 SQLite 事务校验。两位 worker 竞争时，只能一位提交同一派发；取消在事务前发生会使旧资格校验失败，不能启动子进程。批次的每个请求与回执进入原有追加式哈希链。

单项目执行由本机内核文件锁串行保护。worker 继承同一锁描述符，控制进程中断而子进程仍活着时，锁继续被持有。恢复和重试必须实际取得该锁；不根据旧 PID、超时、日志或锁文件存在与否推断进程死亡。锁文件被替换会使保存的身份不一致，停止自动恢复；这需要操作者核查或记录迁移，不能把新文件当作旧执行已结束的证明。

此契约适用于本机 POSIX 状态目录。复制带有未完成请求的数据库到其他目录或机器不能提供旧进程已结束的证据；跨主机调度与该类迁移核查尚未实现。

## 固定工具进程

worker 的入口、工具表和参数由主机固定。使用隔离 Python 启动选项，只传本地状态、项目、已授权工具、冻结 hash 和时限；环境只保留固定的 PATH／语言／缓存设置，不继承模型 API key、认证信息或用户 PYTHONPATH。stderr 不进入项目记录。

子进程仅运行两项既有只读函数，读取前校验大小与来源哈希，完成后再次校验实际使用的来源及上下文。输出有大小和结构限制，失败不保留部分结果为成功。取消或超时终止实际 Popen 子进程并核实结束；无法确认结束时保留中断／未知和整份预留额度，内核锁继续阻止新执行。

本队列不接收 shell、任意 Python／R、模型给出的参数或外部 URL。新增任意分析代码仍需独立接入现有受限分析执行流程。没有新增不受限的分析回退。

## 中断与重试

恢复仅针对新队列登记的请求。失去完成回执且控制／子进程均不再持锁时，追加中断回执，记录恢复理由、未知原结果和保守预算计入。显式重试又追加授权记录与新 attempt，不改写旧请求。活跃的内核锁或锁版本变化会阻止恢复／重试。

升级前的单独工具请求／回执原样保留，不补造预算、耗时或锁身份。新建批次是一次明确记录的新执行意图，历史旧回执不会被静默改标为队列执行。如果旧版工具请求缺少回执，后续派发会受阻，需要独立核查迁移；不得自动重放。

## CLI

```sh
uv run python scripts/research_batches.py --state-dir "$VBT_UC_STATE" \
  --program osmr-uc-independent enqueue --proposal-id ACTUAL_PROPOSAL_ID \
  --task audit_sources --task interaction_card \
  --dependencies-json '{"interaction_card":["audit_sources"]}' \
  --max-attempts 4 --max-seconds 60 --per-task-seconds 15 \
  --author "实际任务与预算记录人"

uv run python scripts/research_batches.py --state-dir "$VBT_UC_STATE" \
  --program osmr-uc-independent run --batch ACTUAL_BATCH_ID \
  --author "实际执行记录人"
```

任务 ID 以实际草案为准。恢复与重试分别操作：

```sh
uv run python scripts/research_batches.py --state-dir "$VBT_UC_STATE" \
  --program osmr-uc-independent recover --batch ACTUAL_BATCH_ID \
  --reason "实际核查依据，至少十字符" --author "实际核查记录人"

uv run python scripts/research_batches.py --state-dir "$VBT_UC_STATE" \
  --program osmr-uc-independent retry --batch ACTUAL_BATCH_ID --task ACTUAL_TASK_ID \
  --reason "核查输入后决定重试的依据，至少十字符" --author "实际记录人"

uv run python scripts/research_batches.py --state-dir "$VBT_UC_STATE" \
  --program osmr-uc-independent export --output /tmp/uc-task-batches-new.json
```

导出拒绝覆盖已有文件。重试只重新排队；仍需显式运行。已完成任务重复运行不增加请求或事件；旧单任务接口返回历史回执时明确标注未重新执行，不把它说成新的来源核查。

## 实际 UC 与工程验收

独立本地 UC 状态从上一轮程序库一致性备份建立，原实例保持运行。实际建立一个两任务批次，先核对 3 个绑定来源，再提取 4 行已有交互结果。两项均实际完成，共计入 0.186743 秒；再次运行同一批次没有新增请求或事件。没有重拟合模型或下载数据。

真实项目仍有 3 条待审阅证据，独立科学审阅为 0，模型服务请求为 0，没有新实验、实验结果或研发决定。费用未计量。超时、取消、双 worker、中断、活子进程阻止恢复和显式重试等故障用例使用合成工程输入，不与这次 UC 实际运行混报。

完整工作台回归 **1777 passed / 1 skipped**（80.17 秒）；跳过项缺少未分发的原始公司披露材料。九文件定向验证 **201 passed**。测试覆盖真实持久存储、实际受限入口子进程、继承锁、凭据环境剔除、CSRF、HTTP 导出、依赖及预算约束。尚无跨主机或生产长期运行验收，不代表科学结论或产品相对优势。
