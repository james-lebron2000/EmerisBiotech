# 临床资产研究的检索、证据和历史入口

本轮在已有深蓝与青绿工作台基础上，由 UI subagent 实现页面交互，独立 subagent 核查路由、导出、安全和历史范围，主任务整合样式、运行版本与浏览器验收。范围是本地单用户工作台的可用性。

## 研究路径

- `/assets` 公司入口支持上市市场与公司名称、证券代码、已存申办方联合检索。进入公司及返回入口保留目录上下文；分页保留市场和搜索词。重复的查询边界与失败原因默认折叠，关键状态仍直接可见。
- `/market` 保留原表格，并提供折叠卡片视图。每项试验可进入同公司、同 NCT 的登记用药关联和登记变更。卡片保留干预名称、适应症、来源日期、观测日期及原文校验记录。
- 检索条件显示可单项移除的标签。清除其他条件时保留公司上下文；切换显示方式和分页保留筛选。
- 变更先按市场、公司和明确 NCT 过滤再取最近十条。普通关键词、阶段和登记状态不用于推算历史状态，页面明确说明这个范围。展开可查看完整 before/after 和采集运行编号。
- CSV 导出继续保存全部匹配结果的快照；显示方式和当前页不改变导出范围。原 POST、Host、Origin 和 token 校验保持有效。

## 解释边界

已存登记观测、临床成功、药物权益和完整管线覆盖分别核实。名称卡片的阶段和角色汇总仍按原有规则处理：条件命中名称后，保留该名称全部试验依据，不推断药物最高阶段。没有已存变更不能推断没有研发变化。校验值展示不等于本页重新检验原件。

本轮不下载研究数据，不更改主体关联、不提交科学判断，不修改研究运行和原始证据。

恢复沿用本机受管服务流程：先核对并停止相同 launchd 实例，再保存当前文件和一致的数据库备份，恢复选定发布版本，核对 SHA 后重新加载；不能在服务运行时覆盖活动 SQLite。

## 后续迭代：长页导航与公司上下文

本次由两个 subagent 分别实现资产长页导航和跨页面上下文链接，并交叉只读审查对方的改动；主任务整合样式、执行完整回归和本机发布。UI 代码提交为 `cb351d449dd4b977561664435fc6ce66204dc8b6`。

- 公司资产页增加悬浮页内导航，可直达筛选、名称与试验依据、采集状态。三个目标均具有独立 ID 和键盘焦点；返回公司入口继续保留原市场、搜索词及公司目录页码。
- 结果顶部和底部均有分页，显示当前页和总页数；翻页保留原有公司、筛选、排序和目录上下文，并定位到结果区。空结果不生成虚构页码，单页明确显示第 1 / 1 页。
- 公司披露页返回登记和资产时保留证券主体。有效的关联 NCT 新增同公司本地登记入口；非法 NCT 不生成该入口。
- 市场页头部的资产入口保留公司。覆盖页的未关联公司入口改为申办方关联页面，并传入市场与证券代码。

完整整合回归 **1,265 项通过，0 失败、0 错误、0 跳过**。两个 subagent 的聚焦结果分别为 75 和 123 项通过，与完整回归重叠，不相加。测试实际跟随生成链接进入目标渲染器，覆盖公司隔离、无效 NCT、转义、顶底分页一致性、失效页码和原有权限约束。

实际浏览器核对了以下路径：恒瑞公司资产页进入结果；在顶部从第 1 页翻至第 2 页，保留公司并显示第 51–100 个登记名称；公司披露中的 `NCT06385678` 进入同公司本地登记并得到一条证券—试验关联；随后带该 NCT 返回登记用药研究。名称命中后保留该名称全部试验依据，不能把登记名称数当作独立资产数，或把结果中其他 NCT 误解为新的同一试验。

1440px 桌面两列名称卡各 557px，390px 手机单列，两个视口均未出现页面级横向溢出。实测页内跳转后标题在悬浮导航下方可见；导航与翻页触控区域至少 44px。临时视口覆盖已清除，并保留研究页面供用户使用。

本机受管服务发布前保存了五个旧 UI 模块、launchd 配置和四个一致 SQLite 备份，备份均通过 `quick_check=ok`。新服务配置、PID、端口归属和 HTTP 响应核对通过；57 个运行模块逐文件 SHA 与该代码提交一致。发布前正在执行的两项采集任务已由新实例接续，保留原任务 ID 与尝试记录。本次没有覆盖活动数据库或修改原始研究数据。

## 本轮迭代：试验依据、历史回看与详情层级

本轮使用三个 subagent：资产页实施、独立界面审查、服务连接生命周期诊断；主任务整合历史页、研究详情、样式与发布。实现提交为 `4ab69bd`，起始假设标注修订为 `5b412b7`。

- 精确 NCT 检索增加同公司本地登记和登记变更入口。卡片把命中的试验依据稳定排到最前，并明确筛选作用于登记名称，全部其他来源、原文阶段及分母继续保留。没有名称命中时，不推定为没有登记。
- 折叠试验摘要分层呈现 NCT、完整试验标题、登记状态和阶段。手机标题仅在摘要中限制为两行，展开后仍有完整正文。默认折叠，权益和历史批次边界继续显示。
- 历史页支持逐项移除筛选条件，保留其余条件并返回第一页。结果顶部和底部显示一致的页码；进入详情和返回继续保留筛选。空结果不虚构页码。
- 研究详情先显示四项独立状态和研究摘要，再显示中文命名的证据附件。技术文件名与执行日志放入可展开区域。完整性只转录保存字段，签署字段存在不代表有效签名或审批；缺失状态保持未知。
- 研究循环标题明确标为原始研究假设，保存的修订或终止决策在摘要中呈现。首页改为“工作区研究记录”，不把按编号排序的部分记录声称为最近研究。
- 非对象计划、空决策、异常结果行等保留为可查看的待核实记录，不修改原始文件，也不把损坏或缺失结果表述为阴性。笔记表单的可见字段补齐标签关联。

最终完整回归 **1,395 项通过，0 失败、0 错误、0 跳过**，耗时 176.41 秒。独立聚焦审查结果与完整回归重叠，不相加。首次新增 FD 用例曾错误假设缺失配置默认值，已改为 API 的显式默认参数，并重新执行完整回归；失败记录保留。

本机服务此前虽监听端口，却在 HTTP 头之前重置连接。只读进程观察显示 256 个数字 FD，其中市场数据库和 WAL 各 125 个，与 launchd 软限制相符；未取得系统调用级 EMFILE 记录。短期连接现在在事务提交或回滚后显式关闭，持久 Registry/Portfolio 连接保留既有关闭路径。独立子进程在 FD 上限 64、关闭垃圾回收时完成 200 轮读取和 80 次 HTTP 请求；正式受管实例连续 200 次页面 GET 全部成功，观察到 FD 从 7 到 8，保持有界。
