# Patient Scenario Lab

English-only synthetic patient showcase. Patient identifier: **P001**, with no DEMO prefix. All clinical-looking context, treatments and follow-up observations are fictional. This is not a clinical prediction service.

## Two delivery surfaces

- `/patient-lab` is integrated into the existing workbench. Runs are stored in a separate local SQLite database, protected by the existing Host, Origin, CSRF and script-free CSP boundaries.
- `web/patient-lab` is the public English showcase. Its versioned templates are generated by the same Python engine. Each visitor saves records in their own browser. There is no public patient-upload endpoint, shared visitor database or paid provider call.

The new patient project's interface, documentation, errors, fixture and exports use English. Legacy workbench and Predome pages outside the patient project retain their existing locale. Earlier local runs are historical artifacts and are not rewritten to translate their contents. New snapshots use `patient-p001-v2-en`.

## Local workbench launch

```sh
uv sync --extra dev --frozen
uv run python scripts/serve_patient_lab.py \
  --state-dir "$HOME/Library/Application Support/VirtualBiotech/patient-lab-showcase-en" \
  --port 18766
```

Open <http://127.0.0.1:18766/patient-lab>. This launcher does not start collection workers. Stop with Ctrl-C; restart with the same state directory to reopen stored runs. It is a local, single-user process without automatic restart.

## Complete workflow

1. Review clinical context and expand biological/missing information.
2. Choose low (20%) or high (45%) initial resistance; run and save a baseline scenario.
3. Compare fictional A, B and A+B at any week from 0 to 24. Viewing a saved run does not modify it.
4. Inspect prognosis illustrations and evidence boundaries. Export the record as JSON.
5. Add the predefined week-6 observation, then week-12 observation. Each creates a new version and preserves its parent.
6. Reopen earlier records. Repeated follow-up requests return the existing child rather than overwrite history.

The public showcase starts with an explicitly unsaved preview of precomputed outputs. Saving creates browser-local run metadata bound to a verified template. Each export includes the canonical model template, its SHA-256, input hash and separate run/parent metadata. The local workbench export additionally hashes its complete persisted result. Neither checksum authenticates an author or establishes clinical validity.

## Explicit toy model

For current burden B, initial resistant fraction r and weeks t:

- Sensitive population: `B * (1-r) * exp(-k*t)`.
- Resistant population: `B * r * exp(g*t)`.
- Burden index: the sum of those populations.
- Illustrative span: burden multiplied by `1 ± (0.04 + 0.012*t)`.

The span is not a calibrated prediction or confidence interval. All coefficients and treatments are fictional. Age, diagnosis, anatomical sites and molecular fields are context only; they do not enter the model. There is no actual multi-lesion, PK/PD, omics-informed or causal treatment-effect model.

Survival curves are separate fixed mathematical illustrations: `100 * exp(-(month/scale)^1.28)` with scale 21, 25 or 29 months. They are not derived from patient data, tumor trajectories or follow-up. Clinical response, PFS, OS, toxicity and quality of life remain null/unavailable.

## Follow-up and integrity

Predefined synthetic burden observations are 100 at baseline, 82 at week 6 and 69 at week 12. Fictional A is recorded as received treatment. Snapshots include only observations available at their cutoff. The full fixture is public and is not a blinded evaluation.

An update resets current burden and retains the resistance assumption. It does not retrain a model or infer a new resistant fraction. Comparing the prior A trajectory with a synthetic observation tests data flow, not predictive accuracy. Other plans have no observed counterfactual outcomes.

The workbench stores runs in `patient-lab.sqlite3` under its local state directory. New baseline requests create independent records; a unique parent link makes repeated/concurrent follow-ups idempotent. The public showcase stores up to 200 records locally and lists the latest 30. Reloading validates record structure, template hashes and parent links. Storage failures are shown as failures, not successful saves. No browser history is uploaded.

`execution=succeeded`, `scientific_review=not_performed` and `clinical_use=false` remain separate. Unsupported real patients, real sources, doses or model parameters are rejected by the local request contract.

## Public build

```sh
uv run python scripts/build_patient_site.py --out /absolute/output/dist
```

The build copies the English HTML/JS/CSS and exports all six combinations (two resistance assumptions × cutoffs 0, 6 and 12) from the authoritative Python engine. Browser SHA-256 checks verify canonical template bytes before use. Browser code selects and plots those results; it does not reproduce model equations. Hosting source and deployment identity are maintained by the Sites publishing workflow.

## Checks

```sh
uv run pytest -q tests/test_patient_lab.py tests/test_patient_lab_http.py \
  tests/test_ui_shell.py tests/test_dashboard_view.py
uv run pytest -q tests
```

Browser QA uses real production HTML, actual loopback HTTP, isolated state and no API fixtures:

```sh
npm install --no-save --package-lock=false playwright@1.56.1
npx playwright install --with-deps chromium
node tests/ui_patient_lab.cjs
```

`VBT_PYTHON`, `PLAYWRIGHT_MODULE`, `CHROMIUM_EXECUTABLE` and `PATIENT_LAB_QA_DIR` select existing tools and optional local screenshot outputs. The public-site browser suite uses `PATIENT_PUBLIC_URL` with a local or published URL.

Historical local regression: 1,638 passed / 1 skipped; final first-release macOS CI: 1,636 passed / 3 skipped, plus real-HTTP browser flow. Missing source captures and unavailable platform/environment checks are not passes. Latest PR checks report the English/public-release results separately.

## Scope of future work

Real patient use requires an authorized disease-specific longitudinal dataset, appropriate endpoint models, independent review and validation. The showcase does not unlock real treatment selection, prognosis, clinical workflows or prescribing.
