# 历史管线图表的工作台展示

本轮仅修改 `disclosure_view.py`、对应 UI 测试和本文档。未下载资料、修改生产数据库、重启服务或执行 Git 操作。

工作台将网页来源、历史 PDF 来源及 `offline_reviewed_bundle` 离线历史来源分别标记。来源汇总展示配置来源数、离线来源数、当前可核验结构化来源数、失败或受阻来源数。已有旧成功批次但最新尝试失败时，这些状态可以重叠；公司没有配置来源时继续显示明确缺口。所有数量均不代表完整管线或独立资产总数。

## 读取门禁与日期

页面先冻结来源批次及尝试记录，再对每个成功批次调用 `disclosures.capture_integrity(market, capture)`。只有 `integrity_status=verified` 的批次可以产生表格观察和阶段选项。原件缺失、归档或观察损坏时，页面显示原件完整性受阻、可核验观察数量未知，隐藏相关观察；原运行的执行成功状态保留为独立历史记录。门禁调用不占用页面的 SQLite 读事务。

每条观察保留 capture metadata。历史来源优先读取 `original_retrieved_at`，兼容 `retrieved_at`；`imported_at` 单独作为本地验收入库时间。capture.finished 不被解释为冻结 PDF 的原件取回时间。

内容截止日期按 `as_of_precision` 展示。`unresolved_report_date` 显示“未知（报告日期尚未确定）”；`reporting_period_original` 单独展示，不能从年报年度猜测报告日期或发布日期。`published_at=None` 保持尚未提供。

## 原文、审查与操作

物理 PDF 页、印刷页码、图表行号、行坐标、药物单元格及阶段列坐标保存在每行的原文定位详情中。来源批次、原件 SHA-256、转录包 SHA-256、原件相对引用均可查看。

阶段筛选来自当前可核验成功批次的实际原文值，保留 `Clinical POC`、`Phase II/III`、`Pre-clinical` 等，不转换成登记临床分期，也不推断最高阶段。靶点、药物形式或阶段缺失时保留未提供。图表注释、研究标签、脚注原文仅作为来源观察。

助理视觉转录审查明确标记为非人工签署，药物权益未独立核验、科学审查待完成。每个离线来源使用原有受 token 保护的 POST 动作，按钮为“验收本地历史原件”，页面明确该操作不进行定时网络刷新或下载。

公司、来源、关键词和原文阶段仍可组合 GET 筛选，分页保留这些参数。新增用户和来源文本均进行 HTML 转义，来源链接使用既有安全链接函数。

## 聚焦验证

`tests/test_disclosure_view.py` 与 `tests/test_disclosures.py` 联合运行 **80 passed（1.05 秒）**。7 项新增 UI 测试使用明确的合成视图契约，覆盖历史日期、原件取回与导入区分、未知报告日期、定位与非人工审查、原文阶段组合筛选、受阻原件隐藏观察、网页归档篡改和转义。合成历史视图测试 mock 读取门禁，不声称真实 PDF 验收通过；真实原件门禁与入库验收由核心模块及主 agent 独立执行。

本轮没有完成真实浏览器或客户部署验收，相关操作由主 agent 执行。
