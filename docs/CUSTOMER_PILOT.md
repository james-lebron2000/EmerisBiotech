# EmerisBiotech 客户试用流程

本版可用于研究分析员在受控工作区浏览市场候选、核对临床登记和记录分类判断。当前市场目录识别与申办方采集覆盖仍在扩展，尚未通过全药企/全管线覆盖核验，也未建立临床预测或投资收益成绩。

## 常用入口

- `/coverage`：按美股、A股、港股查看候选数量、申办方关联、已抓取、零结果、过期、失败和来源缺口。也兼容 `/market/progress`。
- `/market`：按公司、药物、适应症、临床阶段和状态检索登记；可查看来源链接和原更新时间。
- `/assets?company=US:PFE`：按公司浏览候选药物名称与对应试验，区分实验组、比较组和角色未记载。
- `/disclosures`：按公司查看官方管线披露、抓取与内容日期、访问／解析缺口及保守的同公司登记关联。
- `/market` 结果页的导出按钮：生成带行数、来源、批次及 SHA-256 清单的 CSV 固定快照。
- `/records`：原研究工作流的历史记录。

推荐从覆盖页面选择一家公司，查看其临床登记，再进入候选药物关联。试验 COMPLETE 状态不代表结局成功。不同证券代码、不同药物代号和不同试验均保留原始标识；不要把关联行数作为独立药物数量。

## 启动与日常操作

```sh
uv sync --extra dev --frozen
uv run vbt --workspace "$PWD" market universe all
uv run vbt --workspace "$PWD" market expand all
uv run vbt --workspace "$PWD" market enqueue all
uv run vbt --workspace "$PWD" workbench --port 18764
```

`expand` 对当前证券目录执行可解释筛选，并补入有临床登记来源及当前证券名称核对的种子映射。自动识别、来源配置映射保留独立审查待完成状态；不会覆盖既有不同别名。`enqueue` 只入队，工作台或独立 worker 运行后才抓取。进程需要持续运行；任务最多并发两项。

在页面中可以刷新识别、补入映射、将已关联公司全部入队，随后按失败/尚未关联筛选。无法规范化的特殊证券代码单独列数并保留原记录，不能剥除 `$` 后强行关联普通股。名称或行业提示不足的证券列为“尚未识别”，不能按非药企自动排除。

## 持续采集与私有部署

本地工作台自带采集 worker。私有部署使用单独的 `vbt.market_worker`，与网页共享本机卷上的状态库及工作区。`deploy/cloud/compose.yaml` 为 app、worker、鉴权 HTTPS 网关分工；app 无公网宿主端口，worker 独立出网。公开部署需要配置域名及网关凭据，不要直接将研究后端暴露到公网。

软件环境需要系统 curl 和可信 CA。没有模型密钥也能采集、检索及记录分类。界面与持久任务开关不依赖模型调用。

## 可追溯与恢复

每次采集保存原响应、请求URL、SHA-256和取回时间。公司试验抓取完成所有别名/分页后，当前记录、变更、批次关联和成功标记同一事务发布。失败、分页不完整、取消的抓取不会发布半成品；已下载部分留待检查。历史记录未在新批次出现时保留为历史观察，不能据此推断药物终止。

持久队列去重、限制并发、有限重试；进程意外中断后恢复任务。租约带唯一所有者 token，过期旧任务不能删掉或发布覆盖新任务的数据。取消为尽力中断，当前网络请求可能要到其超时/返回后才停止。

SQLite 状态目录与工作区分别备份；活动数据库须在本机卷。使用 SQLite backup API 取得一致副本，恢复时停止服务并还原数据库及整个 `artifacts/market`。原研究的 `vbt restore` 不自动恢复市场数据库。

## 对客户开放前的剩余门槛

- 根据客户关注范围核对药企主表、未分类名单、母子公司和英文申办方别名。
- 对 IR 管线页、年报与中国临床登记逐项对照，记录漏检、错误归属和药物权益。
- 完成目标部署环境的鉴权、证书、备份恢复、长期运行和可达性验收。
- 约定实际可兑现的数据来源、更新频率与覆盖分母，再承诺客户 SLA。

本版不把浏览器演示、采集成功、分类审核或工程测试当作上述门槛全部通过。

## 继续扩大申办方关联

`/mapping` 提供未关联公司检索、下一批（最多20家）申办方查找、待核对建议和已记录的主体判断。平台清理英文证券描述后向官方登记库查询，保留规范名相符、主体歧义、零结果、需要准确英文名、分页不完整和失败等状态。

关联建议保留候选公司内容哈希、NCT证据和原始抓取批次，自动检索建议为待核对。另有严格限定的 Nasdaq 双源名称核对接口，可记录 automated_source_review；它重新验证本地官方目录和指定 NCT 原文件，并明确不代表人工签署。分析员核对证券主体与申办方法人关系后，可以接受或排除；接受才登记映射并排队采集临床记录。既有不同别名、已变更的候选依据和已经处理的建议都不会被自动覆盖。中文公司名称不会被机器翻译后直接归属。

自动更新开启后，目录变更会触发重新识别；每小时最多排队20个未检索且名称可用的主体。官方披露独立每6小时检查。持续运行依赖 worker、网络及源站可访问性，尚不能承诺源站事件即时推送。
