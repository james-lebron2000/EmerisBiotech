# 临床资产工作台：本地试用与界面验收

本轮由 UI 实现、独立证据审查与恢复验证三个子任务协作，主任务负责合并、受管服务发布和浏览器实机检查。交付范围按用户选择固定为受控本地试用版及可部署源码包。源码提交 `2145c10` 完成覆盖与证据接入，`94e6f1d` 修复实际浏览器附件交互；本机运行的 61 个 Python 模块均与 `94e6f1d` 逐字节一致。

## 实际可用流程

1. 从“临床资产”选择证券主体，按药物名称、NCT 或适应症查询；用药角色与其余条件组合，移除一项条件保留其他条件。
2. 名称卡逐层展开到具体试验，保留阶段原文、来源时间、本地观察及批次。外部当前登记页与本地已存观察分别提供入口。
3. 从试验跳到同公司的本地登记，浏览器返回后保留公司、关键词及用药角色。
4. 公司披露卡直接提供该版本的封存网页源文本、JSON 记录或历史 PDF 下载。读入口重新验证原件及所有观察行；来源、公司、版本或 SHA 不一致时拒绝读取。
5. 历史页可查看过往记录，分开筛选执行与科学审查状态，并保留合成工程测试标记、保存的时间及备份范围。

内部原件和 JSON 使用同页导航。实机发现新窗口入口没有在当前内嵌浏览器打开，已改为同页；历史 PDF 的内嵌预览出现空白，已改为明确的附件下载。PDF 下载继续保留 sandbox、nosniff 和原字节校验，未放松浏览器保护。

## 运行与恢复边界

本机服务仅绑定回环地址，采用已有受管启动配置及干净的执行环境。它是可信本机用户的单用户研究工作区；不将 CSRF、Host 检查或回环地址称为多租户权限隔离。源码包的独立安装和启动步骤见 `LOCAL_TRIAL_PACKAGE_2026-10-19.md`。

首轮发布保存旧源码、配置及四个一致 SQLite 检查点；附件跟进只备份两个源文件和配置，不重复复制状态或原件。两种备份范围在机器记录中分别写明，均不能单独称为完整灾备。

独立市场恢复演练复用历史冷备，在外置盘保留归档和恢复后的原件，本机保留恢复状态。复制已完成，但曾因本机可用空间跌破 1.5 GiB 门禁停止；最终原件、四库及身份附件复验以独立恢复收据为准，不以复制完成或当前服务可访问代替验收。该演练也不替代历史研究记录、客户云端或异地灾备验收。

本机空闲空间曾在约 0.3–3.8 GB 间波动，系统观测到较高 swap 使用；未据此归因某个应用，未删除原件或既有备份。仅清理本轮已经结束的可再生成测试目录，并保留源码、JUnit、截图和清理记录。部署到其他机器前需重新核实容量、依赖、权限与备份；本轮不提供预构建镜像或云环境验收结论。

工程和界面验收不构成前瞻临床预测、药物权益确认或投资收益验证。
