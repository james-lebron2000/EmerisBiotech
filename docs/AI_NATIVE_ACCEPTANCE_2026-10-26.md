# Issue #4：AI 研究草案与执行回执验收

## 问题与实现

当前项目需要让 AI 研究建议使用同一份有版本的证据，并连接真实、受约束的工具。对应 [Issue #4](https://github.com/james-lebron2000/EmerisBiotech/issues/4)，本轮发布此前本地 UC 双角色项目基础，以及冻结上下文、结构化草案、八类风险、任务和回执模块。具体契约见 [AI 研究接口](AI_NATIVE_RESEARCH.md)。

实现分支从远端 main 的 `d17518bc0456e2d24845a7cc3e1c6e4e6bad1416` 建立。保留远端 Predome 应用、CI 和 SQLite 回归改动，没有用较早本地版本覆盖它们。原工作区中其他未提交文件、数据和运行记录未纳入提交。

## 实际 UC 运行

当前助手会话基于冻结项目内容生成一份草案，含八类风险与五项任务。来源记录为 assistant_session，具体模型标识未独立认证。不是产品后台自动调用模型，也没有伪装成独立科学审阅。

两项主机只读工具实际运行：来源核对覆盖三个绑定附件，交互证据卡提取四行封存结果。另在实际浏览器通过表单再次运行交互提取并确认新回执保存。三次执行回执均待科学审阅；没有形成研发/BD 决定或真实实验。

已核对实际页面、草案来源、风险/任务、成功回执及来源哈希。默认窄视口中的风险展示改为卡片，引用编号收进可展开详情；最终页面另做定向回归和视觉核对。

## 剩余范围

本轮提供 Issue 的软件实现与可审阅分支/PR；不自动合并、不升级生产服务、不发布云端。产品内自动模型服务、任务预算和调度、跨任务学习、真实实验以及独立产品价值比较仍待建设。总目标保持进行中。

发布后复核补充：上下文 schema v2 还包含导入绑定清单的版本。即使文字证据未变，来源重新绑定也使旧草案失效。新增针对该情形的回归；UC 原草案保留为历史，同一草案按 v2 重录并重新运行两项只读工具，不计作新的独立模型推理。
