# Predome 开发与验证工作流

本次参考用户提供的 OpenCode AGENTS.md，并将引用固定到[提交 bcd713e2b71b433474d99fb1d29900c492c319a3](https://github.com/anomalyco/opencode/blob/bcd713e2b71b433474d99fb1d29900c492c319a3/AGENTS.md)。这里采用适合现有 Python 与静态 JavaScript 项目的工程原则，不复制整份指南，也不引入新的预测算法、训练、认证或部署能力。

## 采用的原则

| 原则 | 在本项目中的落实 |
|---|---|
| 依赖方向明确 | `scripts/` 调用 `emeris_live/`，运行库不反向导入命令脚本；静态页面使用公开的接口投影 |
| 在所属边界验证 | API、文件、模型响应各自接收未知输入；来源哈希、权限和冻结目标仍在各自信任边界核验 |
| 测试真实实现 | Python 测试调用生产实现；浏览器 fixture 加载实际 `static/` 文件；临时文件、SQLite 和传输层替身控制副作用 |
| 检查入口一致 | Predome 本地与 CI 使用包内 `scripts/check.py`；根工作台保持现有独立回归 |
| 记录与派生视图区分 | 原始来源、冻结输入和失败记录保持不变；页面和报告消费可核验的投影 |

直接导入检查只能识别 Python AST 中显式声明的反向依赖，不能证明任意动态导入或运行时代码安全。检查通过也不授予数据访问、模型调用或服务器部署权限。

### 2026-10-27 工作流复核

重新核对上游指南，`AGENTS.md` 的最新提交仍是上述固定版本。本轮发现，历史部署命令用 `assert` 核对账本或安装包哈希，启用 Python 优化模式后整条校验会被移除。离线复现中，将期望账本哈希设为错误值，原命令在 `python -O` 下仍以成功退出，且没有读取账本。

现已将这些必需校验以及两个历史部署验证器、旧试跑准备入口中的校验改为显式 `ValueError`。修改的是代码，不运行旧准备入口，也不生成或替换历史资料、输入、预测、签名或部署。历史验证器继续核对其原有 1.1.8 合同与固定进程清单；它们不属于当前 1.2.9 部署流程，本轮没有将其加入当前部署包。

统一静态检查增加 `deploy/` 的 Python 语法检查，并拒绝 `emeris_live/`、`scripts/`、`deploy/` 中的裸 `assert`，测试中的断言不受影响。Python 字符串内的远端程序不在 AST 断言检查覆盖范围内，因此直接执行实际交付的程序，分别验证普通模式、`-O` 和 `PYTHONOPTIMIZE=1`：错误哈希必须失败，安装包校验失败时不得覆盖已有 bootstrap，账本事件不得改变。历史验证器另在普通模式与 `-O` 下验证正常回执和拒绝路径。这些测试加入现有 `ci-tests.txt`，由同一本地／CI入口执行。

本轮验收使用临时文件、临时 SQLite 和 HTTP／系统命令边界 fixture；不访问 SSH、生产数据库或模型服务。通过只说明上述工程校验在所测条件下有效。

### 公开内容规则与独立报告

再次核对上游 `dev` 中 `AGENTS.md` 的最近文件提交仍为 `bcd713e2b71b433474d99fb1d29900c492c319a3`。本轮按“依赖方向”和“在所属边界验证”的原则审查实际产品，发现两个相连的问题：公开摘要会原样保留模型误回显的密钥样式文本，而简报下载会拒绝同类文本；纯报告生成器又通过懒导入 Web 路由来复用 URL 校验。

共享规则现放在仅依赖标准库的 `emeris_live/arena_public_contract.py`，由公开接口和报告生成器共同使用。公开摘要遇到已识别的凭据样式时不发布该摘要；预测方向、模型版本、失败状态和原始时间保持不变。简报仍在导出边界核验完整公开记录。这是限定模式的发布过滤，不是对任意秘密或个人信息的完备检测。

验证使用合成占位文本和实际公开生产方，检查总览、单项详情、JSON、ZIP的一致性，并比较原始输入前后不变。另在独立进程中执行实际报告构建，阻止导入 Web、提供商及数据库模块，确保复用规则不会把服务层依赖带回报告层。部署清单同步包含共享模块，避免源码可运行而固定基线部署包缺文件。

### 完整编译检查

本轮在临时包中复现：`ast.parse()` 会接受函数外的 `return`、循环外的 `break`、模块级 `nonlocal` 和重复关键字参数，而 Python 编译器会拒绝这些源码。若模块没有被所选测试导入，原统一检查入口就可能误报成功。

`check_runtime()` 现在对实际 AST 执行 `compile(..., 'exec')`，补齐编译上下文检查，不执行源码或生成 `.pyc`。回归通过实际 CLI 分别检查运行库、命令脚本和部署目录；错误只显示文件与行号，不回显源码中的合成敏感标记。另以顶层 `raise RuntimeError` 证明静态检查不会运行代码。原生产断言、反向依赖与证据守卫保持有效。CI仍沿用同一入口，没有另建一套检查实现。

## 命令与前置条件

先按 [README](../README.md) 为 Predome 建立 Python 3.11 环境并安装既有锁定依赖。以下命令在 `apps/predome` 内执行；若使用 README 中的虚拟环境，将 `python` 换成 `.venv/bin/python`。

| 命令 | 范围 | 前置条件 |
|---|---|---|
| `python scripts/check.py` | 默认 `source`：静态检查及 `ci-tests.txt` 中的源码 fixture 测试 | 源码检出、Python 3.11及测试依赖、Node 22；受控本地冻结路径不存在 |
| `python scripts/check.py --suite static` | 仅静态检查 | Python 3.11、Node 22；不运行 pytest 或浏览器 |
| `python scripts/check.py --suite full` | 静态检查及完整应用 pytest | Python 3.11、Node 22及已获授权、保持原件不变的现有证据；不会下载或生成缺失证据 |
| `python scripts/check.py --browser` | 默认检查后，追加9份受控离线浏览器 fixture | 预装 Node 22、Playwright 1.56.1 及 Chromium；不会自动安装 |
| `python scripts/test_source.py` | 保留兼容的源码 fixture 入口 | 与源码测试相同的隔离条件 |

源码测试守卫针对本地冻结材料的具体路径，不把 Git 中公开的 Arena／专利配置一并认作禁入证据。现有证据不满足源码测试条件时，应使用干净源码检出，或在具有相应授权的环境运行完整测试；不能为通过检查移除守卫、覆盖原件或重新生成预测。

受控路径是 `predome_data/`、`dashboard_data/`、`trial_data/`、`public_data/`、`arena_data/source_snapshots/`，以及默认 `patent_data/` 和各 `patent_data/versions/<version>/` 下的 `raw/`、`ocr/`、`receipts/`。版本化专利的公开 catalog、mapping 和 source 元数据仍可用于源码测试。守卫只检查路径是否存在，不打开原件；原件路径即使为空目录、普通文件或损坏的符号链接也会拒绝。版本根目录及版本目录的符号链接同样拒绝，避免沿链接检查外部资料。检查进程只保留必要系统变量；浏览器检查额外允许指定已有的 Playwright／Chromium 路径，不继承生产状态目录、服务凭据、线上浏览器测试开关或额外测试启动参数。这是子进程配置隔离，不是网络或文件系统沙箱。

已有来源读取逻辑从 `scripts/arena_outcome_inbox.py` 移入 `emeris_live/arena_acquired.py`，CLI保留原有同名入口。这使后续API能够复用同一原件校验实现，不需要导入命令脚本或再写一套校验。此次移动不改变来源、标签或冻结记录。

浏览器检查执行以下实际脚本，页面和 API 请求由 fixture 拦截。公开下载测试另在 `127.0.0.1` 的临时随机端口提供固定 ZIP，服务只处理已知下载路径、结束后关闭。浏览器下载通道不经过普通页面拦截，因此点击附件的传输须使用这个隔离的本机 HTTP 边界；它不连接应用数据库、生产或外部服务。实际产品 ZIP 内容仍由真实 API 测试验证，不能用该传输样例代替：

- `tests/ui_predict_context.cjs`
- `tests/ui_prospective_coverage.cjs`
- `tests/ui_arena.cjs`
- `tests/ui_arena_home.cjs`
- `tests/ui_arena_public.cjs`
- `tests/ui_arena_lab.cjs`
- `tests/ui_trials_readonly.cjs`
- `tests/ui_arena_review.cjs`
- `tests/ui_readout_reviews.cjs`

模型服务的 HTTP 传输层替身和浏览器 API fixture 可继续使用；测试不应为减少 mock 而访问付费模型、真实患者数据或生产数据库。界面验证使用生产组件与实际静态资产，避免另写一份只供截图使用的页面。

仓库根目录的原工作台使用独立的锁定环境和检查命令：

```sh
uv sync --extra dev --frozen
uv run pytest -q tests
```

根工作台和 Predome 的依赖、数据库与测试范围保持独立。完整验收分别记录两边结果，不把某个包的成功描述为整个仓库均已通过。

## 迭代与验收

开始修改前，确认所属模块、原有合同和允许写入的位置。并行任务按文件明确责任；有依赖的修改按顺序合并。公开接口变化应同时检查生产方、页面消费者、版本、文档和相关测试，且不改写已冻结的输入或预测。

消费者核对包含下载报告、活动资料导出和离线验证器，不能只检查页面。此次实际审计发现：页面与指标已采用科学接纳状态，但内部报告仍读取原始来源一致状态，活动导出则因新增字段而中断。修复在临时真实账本和实际 API 上验证；来源一致、已接纳二元结果、Mixed／Inconclusive 与历史回放分别保留。新的公开资料包使用版本2及公开结果1.1；已有版本1资料包仅按原合同离线验证，不能用旧格式重新制作一份当前活动导出。旧报告、ZIP和时间戳均不改写。

测试优先覆盖实际失败方式，如清单越界、原件哈希不符、缺失证据、错误退出码、公开页面泄露内部字段或未公布结果被计分。纯文字或可逆的小调整不需要复制实现逻辑来增加测试数量。

检查记录应写明提交、命令、范围、通过／失败及未满足的条件。源码 fixture 只验证工程行为；授权原件上的检查只验证对应记录性质；线上只读验收只证明所查部署行为；独立科学审核与前瞻预测效度需要各自证据。测试计数不能替代这些条件。

本仓库默认分支为 `main`，当前 Open Forecast 工作继续使用既有 `codex/predome-open-forecast` 分支和 PR #3。提交和 PR 描述说明实际行为、验证与限制，界面变化附真实页面截图，不重写既有历史来调整命名。

### 当前日程更新中的应用

本轮将“原始事实与派生视图分开”应用到读出时间更新：保存经采集和审核的新日程，公开投影单独提供 `current_readout`，原预测的 `readout`、模型输出、生成时间与结果评分保持原样。仅当前正式赛季的精确目标可以接收获批更新；NCT 相同不能代替终点、人群、比较和分析时间点的匹配。未知时间保持空值，不回退成旧日期。

共用日期合同继续由纯标准库模块拥有，公开接口、简报、活动导出与离线验证器共同使用，接口版本更新为 1.2，新活动资料包为版本3。内部界面通过实际生产资产的离线 fixture 验证选择目标、未知时间、不同账号审核与延迟回包切换；真实记录验收单独比较复制运行环境中原有的144条模型记录，没有写入合成审核或预测。详情见[当前日程与原预测窗口](CURRENT_READOUT_UPDATES.md)。

此处账号分离是操作审核要求，不能替代独立科学审核。AVANZAR 的新官方2027日程观察仍缺原始PDF获取及哈希、适用性核验和批准，因此保持待处理；它未被用来改写旧预测或提前判断疗效失败。

### 版本化专利原件的源码隔离

重新查阅上游后，文件最新提交仍为 `bcd713e2b71b433474d99fb1d29900c492c319a3`。按已有的边界校验原则复核新加入的证据版本目录，发现源码测试守卫只覆盖默认专利目录。本地临时包中的 `patent_data/versions/assays-20261027-v2/raw/` 因此被接受，可能让源码检查意外依赖本地原件。

修复放在既有 `source_tests()`，兼容入口与统一检查共用它。回归执行实际命令，确认原件存在时在 pytest 前拒绝、原件保持不变；仅有版本化公开配置时仍可通过。`--suite full` 继续用于获授权的原件环境。这项修复只改善工程检查的范围，不改变专利证据、模型输入、预测或科学审核状态。

### UTC 午夜的测试时钟

真实CI在23:59 UTC收集“次日不可接受”的日期参数，到00:00 UTC执行时已变为当天，导致原本合法的生产校验被测试误判。日期边界测试现共用固定UTC时刻，并只在所属validator的测试范围替换时钟；同时通过实际结果写入路径检查当天可接受、次日拒绝且账本不变。其余测试继续使用原时钟，不延后两天或修改生产校验来规避失败。此修正验证工程日期边界，不新增结果裁定或临床预测能力。

### 跨平台视觉边界

公开页的同一日程更新样例在本机通过、Linux浏览器高出紧凑目标约2像素。修复只减少桌面留白，为字体度量差异保留余量；字号、信息和测试阈值不变。最终静态资产重跑全部9套受控浏览器检查，真实HTTP截图另行更新；测试截图和线上部署继续分开记录。

定位时读取实际计算样式和行高：既有43像素下限使padding调整无效，较后的摘要间距规则又覆盖了原有紧凑值。依据实测调整桌面行高下限、标签留白与间距，并保留诊断输出；不把声明的CSS值或本机测试通过当成跨平台布局已通过。

### 单次请求诊断的合同边界

本轮继续应用已采用的 OpenCode 边界、schema 与真实实现测试原则：标准库模块拥有固定诊断合同，provider 只收集有界的已观察元数据，Agent 和 operator 在各自复制／写入边界复用同一 sanitizer。任意嵌套字典不能直接作为诊断入库；非法诊断置空，原终态、用量和未知费用保留。冻结 hash 也覆盖共享 helper，避免只检查入口文件而遗漏传递依赖变更。

验证使用实际 adapter／Agent、临时文件和 SQLite，并在传输边界使用 fixture；同时核对私有 receipt、公开 API、brief、campaign 和旧 receipt 字节兼容。新 Provider／Agent 版本仅供未来新登记执行，不重写旧失败、扩大时间凭证覆盖或产生重试；本轮仅更新 GitHub 候选，未正式打包、stage 或部署，不操作服务器后台。字段与范围见[单次请求安全诊断](ARENA_ATTEMPT_DIAGNOSTICS.md)。

## 未迁移的设置

OpenCode 的 Bun、TypeScript、Effect、Drizzle、TUI 故事、后台会话服务和 `dev` 分支设置不适用于本项目。这里也没有采用其禁止所有根目录测试的约定、强制动画 SVG，或为了风格统一全面改写 Python 变量与控制流。开发流程的变化不代表新增临床预测、模型训练、独立审核或服务器部署已经完成。
