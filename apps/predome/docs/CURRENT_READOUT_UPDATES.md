# 当前日程与原预测窗口

申办方可能在模型预测后改变读出计划。日程变化必须作为新资料保存；不能修改原预测输入，不能将延期当作未达到主要终点，也不能重新调用模型后冒充事前判断。

## 两种记录

公开投影 `arena-clinical-public-1.2` 始终保留 `target.readout` 原冻结窗口。只有当前正式赛季、同一精确目标的独立获批更新，才额外提供 `target.current_readout`。公开页面优先显示获批当前日程，同时注明预测时的原窗口及原模型输入未改变。尚无合格更新时不生成该字段。

当前日程绑定服务器读取的目标 ID、NCT、终点、人群、治疗比较、成功规则和分析时间点。客户端只选择目标，不提供绑定对象或伪造哈希。药物项目级指引不能直接覆盖精确目标；同一 NCT 下的其他目标、旧赛季、历史回放及独立 pilot 也不自动继承更新。

来源公开时间、实际获取时间、批准时间及原模型时间分别保留。公开版本只显示日程与其来源和完整性摘要，不展示审核人身份、内部依据、提示词或原始模型推理。批准时间来自服务器时钟，不是独立时间戳证明；不同账号的操作审核也不等于独立临床科学审核。

## 团队操作路径

在已有权限的内部“公开结果，独立核验”页面中：

1. 打开已经采集的官方来源候选，核对实际来源文件和 SHA-256。检索索引、完成日期或公司沟通活动日期不能自动作为试验读出日期。
2. 选择匹配同一 NCT 的当前正式 Arena 精确目标，并核对其终点和适用层级。旧版 NCT 日历模式与正式 Arena 更新明确分开。
3. 逐字填写支持日程的原文，以原精度填写单日、月份、季度、半年、年份或明确范围。若官方撤回日程而未提供新时间，使用“读出时间未确认”，日期必须为空，不能填入今天或旧窗口。
4. 提交后仍为待审核。另一位已获授权账号核对来源、时间、精确目标适用性后，记录批准或拒绝。不能自审，决定不可覆盖；后续修订需新提案。
5. 批准后公开展示当前日程与原窗口；预测方向、成功概率、锁定时间、结果和评分均保持原记录。

对应既有 API 为 `POST /api/readout-updates` 和 `POST /api/readout-updates/{proposal_id}/review`，继续要求登录、审核角色和 CSRF。Arena 提案在旧输入字段外增加 `arena_target_id`、`source_granularity`、`applicability=exact_registered_target`，三者必须一起提供。未知时间仅适用于精确 Arena 提案。普通公众不能提交或批准。

## 公开读取与离线报告

公开 GET 通过只读 SQLite 连接和既有加密解码器读取审核记录，不构造会初始化表的审核 Store；缺表表示尚无更新，部分表、摘要或身份绑定不一致则停止发布。它不获取新资料，不创建提案、批准、预测或疗效标签。

Clinical Brief 的 HTML、Markdown、JSON 保留当前与原冻结窗口。新的活动导出为 `predome-public-launch-bundle-3`；旧 bundle 1／2 仅按各自原合同离线验证，不重新导出、重写或申请新时间戳。使用完整仓库内的校验工具，因为新日程合同由共用的纯标准库模块验证。

`publish_public_proof.py` 是固定 20261023 历史档案的发布工具，只接受那份已签 ZIP 的准确字节；不能用它发布新 bundle 3。新版离线校验从完整仓库的 `apps/predome` 运行 `python scripts/public_snapshot_proof.py verify --directory /absolute/extracted-kit`。缺少共用合同模块时会明确拒绝，不能仅复制三个历史脚本后跳过校验。

## 本轮真实资料边界

AVANZAR 的[官方新指引观察](AVANZAR_READOUT_OBSERVATION_20261027.md)定位到 2026-10-26 官方材料的 2027 读出部分。原件获取返回 403，尚无实际 PDF 字节哈希或独立批准，因此它仍是待采集／待审核观察，没有进入正式当前日程。示例和浏览器回归中的获批记录均明确标记为合成 fixture，不代表该真实试验已经获批更新。

这套流程只解决日程及其资料版本接入，不能建立预测准确率、专利增益或临床效能。真实主要终点结果仍需单独获取原件、审核并通过既有结果接纳流程。
