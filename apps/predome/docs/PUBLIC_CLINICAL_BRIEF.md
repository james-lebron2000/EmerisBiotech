# 单试验公开 Clinical Brief

研发人员可以从现有公开比较页下载所选试验的研究资料，在浏览器离线阅读、打印，或将机器可读记录用于复查。页面沿用三个核心模块及一个下载入口，不增加注册表单、聊天或多层导航。原 JSON 下载接口继续保留。

## 内容和范围

`/api/arena/public/targets/{target_id}/brief/download` 读取与页面相同的公开 target-detail 投影，生成四文件 ZIP：

- `clinical-brief.html`：无 JavaScript、无外部字体或样式请求，可离线阅读和打印。
- `clinical-brief.md`：便于研发讨论及版本比较的 Markdown。
- `clinical-record.json`：同一次读取的规范化公开记录快照。
- `manifest.json`：资料生成时间、试验标识、版本，以及前三个文件的大小和 SHA-256。

报告列明确切试验、药物、适应症、主要终点、人群、对照和判定标准；模型名称／版本、原预测时间、方向、执行状态和可核验公开来源与记录保持一致。正式赛季、独立研究 pilot 和历史回放分别标识，不把独立试跑自动计入正式赛季。

前瞻公开比较仅使用同一目标下的 `same_evidence / clinical_only` 条件；历史回放保留其原始范围说明。失败保留在分母；未知校准的概率和置信度保持 N/A；未揭晓不标命中、不排名。混合结果、结果来源待核对、待独立科学接纳等状态保留各自的含义。

## 时间与可复核性

资料生成时间只表示本次导出；它不是原模型生成时间，也不是新的独立时间签名。清单和文件哈希用于检查资料内部一致性，不单独证明发布者身份、原预测时点或临床预测能力。原时间凭证和冻结预测不因下载而改变。

JSON 快照和可读报告来自一次公开投影，避免在两次读取之间跨越结果审核轮次。原 `/api/arena/public/targets/{target_id}/record` 接口保持兼容；之后重新下载可能包含后来追加的公开结果审核，不能用后来的资料冒充更早的版本。

报告只显示公开字段，不包含内部推理、原 Prompt、模型 API 配置、密钥、Token、私有审核身份或未公开数据。外部链接须符合公开 URL 规则，HTML 与 Markdown 内容按输出上下文转义。

公开摘要的发布过滤和 URL 规则由标准库模块 `arena_public_contract.py` 提供，页面投影与离线报告共用。已识别为凭据样式的摘要不发布；模型原始记录保持不变。报告构建只接收公开 DTO，不需要导入 Web 路由、模型提供商或数据库模块。限定模式过滤不能证明任意输入中均不含敏感信息，导出边界仍检查完整公开记录。

## 研发讨论的使用方法

先核对 NCT、主要终点、人群及对照，再比较各模型的方向、失败和不确定项。点击公开来源回到登记库或官方公告；登记完成日期不等于结果公告日期。若结果仍待公布，只讨论判断差异与证据缺口。

实际用户反馈应由获授权的参与者记录其阅读和讨论结果，包括能否找出主要终点、模型判断、失败、一项来源及一个未解决问题。浏览器测试、AI 模拟使用和下载次数不能替代真实用户反馈、商业转化或独立科学验证。

## 验证与发布

测试运行真实的公开投影、API、临时账本与导入 pilot，并检查 ZIP 清单、失败／N/A／非二元结果、输出转义和页面下载入口。实际记录导出另核对原账本字节及前端渲染。验证结果、代码提交、部署包和线上版本分别记录；代码或本地截图更新本身不表示已经部署。
