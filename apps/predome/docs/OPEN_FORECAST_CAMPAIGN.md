# Predome Open Forecast｜公开活动规则

版本：1.0 · 2026-10-22
活动定位：临床研发研究预测公开试运行（pilot）
活动入口：`/arena` · 专利证据：`/arena?view=patents` · 结果比较：`/arena?view=leaderboard`

> **同一试验，多种 AI。事前锁定，结果见证。**
>
> 面对同一项临床试验，不同 AI 会给出怎样的判断？Predome Open Forecast 公开目标、证据、模型输出和冻结记录，让研发人员先看分歧与依据，再等待临床结果检验。
>
> 现在可以查看公开试验、比较模型判断、追溯专利原文并下载记录。真实调用、结果公布和预测验证分别展示；没有实际输出的模型不会获得模拟分数，没有裁定结果的任务不会被记为命中。

## 1. 我们究竟在预测什么

每个任务只预测一个已经登记的临床问题：某项试验，在指定人群、治疗与对照、主要终点和分析时间点下，能否达到预先写明的成功标准。统计学显著、临床意义、药品获批和患者个体获益是不同问题；某个目标的概率不能直接替代其他问题的答案。

用户可以从读出窗口进入目标详情，依次看到：

1. **输入**：试验身份、人群、对照、终点、成功规则、信息截止日期，以及可回溯的公开来源。
2. **输出**：每个模型独立给出的概率或拒答，简洁理由、支持与反对证据、关键假设和未知信息。
3. **追溯**：请求和返回的模型标识、工作流版本、生成与锁定时间、输入输出指纹、用量与成本记录。
4. **验证**：实际公告、与登记目标相符的结果、独立裁定和可计算的概率评分。

读出日历按来源原有精度展示。官方只给出半年或年度窗口时，不推算一个“准确发布日期”；注册库中的主要完成日期也不替代公司读出公告。窗口更新会保留新来源，不能反向改写旧预测。

## 2. 当前试运行与完整赛季

**当前是流程试运行，不代表已完成一个覆盖 12 个独立药物开发项目的赛季。** 公开页面可能同时包含既有冻结档案、当前新运行、尚未运行任务和待确认候选，必须根据其范围标签分别阅读。

| 范围 | 用途 | 能否计入新赛季 |
| --- | --- | --- |
| 既有冻结档案 `archived_research` | 让用户核对原有模型输出、原时间和证据 | 否，独立保留 |
| 当前 pilot | 验证真实接口、冻结流程、来源追溯和比较页面 | 只描述登记的 pilot 范围，不能冒充完整赛季 |
| 研究候选清单 | 发现可能符合条件的未来读出 | 未通过入选与预登记前不计入 |
| 完整赛季 | 在预先登记的固定队列上持续观察未来结果 | 只有符合规则的正式任务纳入对应范围 |

完整首季的**计划规模**为 4 个经过真实调用核对的模型标识、12 个独立药物开发项目，每个项目一个明确主要预测目标。若全部项目和模型均符合条件，同证据轨道计划分配 48 个基础任务；其中两个模型可各分配 12 个加入专利的配对条件，最多新增 24 个任务。**48＋24＝72 是条件满足后的任务配置计划，不是已完成输出数，更不是 72 个独立临床样本。** 拒答、调用失败或缺乏合格专利都会如实留在相应记录中。

完整赛季启动前公布并冻结资产清单、关联项目映射、治疗领域、选择标准、模型与工作流配置、成功规则、预算、统计方案和截止时间。肿瘤项目优先；如胃癌和结直肠癌近期合格目标不足，扩展治疗领域必须在登记前说明。达到 12 个项目也不自动保证统计把握度，更不保证能区分模型优劣。相似机制、同一申办方或同一资产的多项试验仍可能相关。

在完整清单、证据和真实调用条件尚未具备时，继续以 pilot 发布进展，保留未完成项。页面与可下载记录是当前数量和状态的依据，活动宣传不预填成功调用数、准确率或费用。

## 3. 四条比较轨道，分别回答四个问题

| 轨道 | 预先固定的条件 | 允许改变的因素 | 可以得出的结论 |
| --- | --- | --- | --- |
| 同证据 LLM | 目标、证据包、截止时间、提示要求和输出格式 | 底层模型 | 给定相同信息，不同模型如何判断 |
| 统一 Agent | 同一证据审查流程、工具权限、任务和预算规则 | 执行流程的模型 | 模型在同一工作流中的表现如何 |
| 开放 Agent | 同一任务、截止时间和明确预算档位 | 模型组合、工具与工作流 | 某个完整系统在相应条件下是否更有用 |
| 专利前后对照 | 同一目标、临床证据、模型版本和工作流 | 是否加入经过审核的专利证据 | 加入专利如何改变判断；结果裁定后再研究是否改善 |

四轨道是比较设计，不能将四个名称当成四套已经完成验证的系统。当前支持的真实执行路径以服务端运行记录为准：单次预测与“证据审查后预测”分别记录。开放检索或其他工具只有在实际接入、权限和预算冻结、运行记录可追溯时，才能作为开放 Agent 参赛。未执行的轨道不展示虚构模型表现。

模型不得读取竞争模型的预测。共享 Agent 的多阶段调用也必须保留每一阶段的用量、失败和耗时。不同证据量、工具权限、调用次数或预算的输出不混入同一个“最强 LLM”排行榜。价格、上下文长度和能力差异应随版本披露；统一预算表示执行同一预算规则，并不保证不同模型得到完全相同的计算量。

## 4. 证据与专利如何进入预测

每项证据记录公开可得时间、获取时间、来源地址、内容指纹和适用目标。输入包只能包含信息截止前已经公开可得的材料。仅有日期而没有时刻时，不能据此证明某条证据在当天公告之前已经可用；存在时间先后疑问的记录应保留为待核验或历史研究。

专利进入正式预测需要逐项通过以下门槛：

- 可核对的公开文件、公开日和内容指纹；优先权日不代替公开日。
- 可验证的药物结构、序列、代号或其他明确映射；候选交叉引用不自动成为已确认药物身份。
- 原始页码与提取状态。OCR 完成只代表文字提取完成；AI 页面核对也不等于人工科学审核。
- 将权利要求、机制论述、已完成实验和拟开展实验分别标明。动物实验不能被改写为人体临床效应。
- 实验卡保留实验系统、样本量、剂量、对照、终点、结果、单位、出处和缺失项；缺失值留空，不补写。
- 按截止时间核对具体公开成员，避免将后来公开的专利家族内容带回过去。

Dato-DXd 的指定一期 ORR 实验卡已通过两角色 AI 来源与页面核对，可用于本轮研究对照；人工科学审核数为 0，两角色共用基座模型，其错误可能相关。Retatrutide 候选尚未通过身份门槛。候选专利可以公开查阅，并不意味着已经进入模型输入。专利库中的“未进入正式预测”是有意义的证据状态。专利的科学内容审核也不构成权利有效性或自由实施（FTO）意见。

专利对照只对显式登记、核对过输入差异的配对展示概率差值。加入专利后概率从一个值变成另一个值，首先称为**判断变化**；预测是否改善，必须等同一目标的实际结果被裁定，再比较固定任务上的评分。没有可审核专利或完整配对时，展示缺口，不制造“增益”。

## 5. 真实调用、冻结与防止事后挑选

模型名称出现在页面、凭据已经配置、API 调用成功、生成有效预测，是四种不同状态。配置就绪不能证明真实接口已可用；HTTP 成功也不能证明响应满足预测契约。概率、引用或目标定义校验失败时，保留失败，不自动变成一个预测。

通过网关调用时，同时记录网关返回的请求与模型标识。若多个模型别名由同一网关提供，不能宣传为经过四家厂商独立认证；接口返回的名称也不能独立证明底层权重身份。精确版本未知时，应保留未知，不用一个品牌标签掩盖版本变化。

每个任务在运行前登记。原始失败、超时、拒答和未完成都保留，不能只公布成功响应。没有预先登记的重试策略时，不因某次预测“不好看”而修复提示或换模型重跑。需要修复工程问题时，新增版本或追加运行，说明原因，原记录继续保留；不能选择多个回答中事后最有利的一次作为原预测。

正式运行先冻结目标、证据、提示、模型及工作流配置，再生成独立输出。内容哈希用于检查材料是否发生变化；**服务器时间与哈希本身不证明预测在结果公布前已由外部见证**。本次 pilot 已使用 FreeTSA RFC 3161 对登记与输出进行第三方时间戳签名，并通过 OpenSSL 验签；凭证包公开下载，信任前提是固定的第三方 CA，不是法律公证。完整赛季也应在截止前将冻结记录摘要交由独立时间凭证或独立见证渠道保存，并公开可核验的证明、时间和内容对应关系。在没有经过核验的外部证明时，页面明确标记仅有平台记录，不能宣传为“已独立公证的事前战绩”。

即使输入包没有泄漏，也不能完全排除模型预训练记忆。因此，结果尚未公开的未来任务用于前瞻观察；已公布结果上的历史回放另列，不与新赛季混算。每次正式锁定前复核公司公告、会议摘要和试验登记；注册库未贴结果并不证明其他渠道尚未公布。

## 6. 什么情况算有结果，怎样比较模型

目标依次处于“待揭晓”“已公布待裁定”“已裁定”。公告出现后，先核对具体试验、人群、主要终点、分析时点和预设统计规则。独立审核者确认原始出处及首次公开时间后再计分。公告标题中的“积极结果”不能替代预登记的成功定义，次要终点也不能替代指定主要终点。

目标与证据不符、缺少多重性或成功规则、效应值不完整时保留待裁定。延期、商业终止、登记更新或没有积极消息，不自动等于疗效失败。结果更正通过追加记录处理，原始预测与原裁定均可追溯。

成绩同时展示以下信息：

- **完整分母与覆盖率**：全部已登记模型任务是分母。分别报告有效回答、拒答、失败、超时、不可调用和未完成；拒答不变成 0% 概率，未完成也不消失。
- **概率评分**：对符合时间与裁定条件的预测计算 Brier 等分数。Brier 是 `(预测概率 − 实际二元结果)²` 的平均值，越低表示这些任务上的概率误差越小。只对有合法结果标签的任务计算。
- **共同任务比较**：同时展示模型自身有效任务和各模型共同有预测、共同可裁定的任务集合，公开样本数。不能用只回答容易问题的模型与回答所有问题的模型直接比较一个平均数。
- **关联与不确定性**：按药物开发项目处理重复终点和相关试验；重复运行不增加独立项目数。成对评分差异及区间注明适用范围，项目不足或区间不稳定时明确说明。
- **参考值、成本与耗时**：预先固定的参考预测与模型分开列示。成本保留币种、价格来源、用量和估计方法；缺价格或缺用量时显示未知，不显示免费。按配置单价计算的费用不是实际账单，不自动换算货币。

尚无共同裁定结果时只展示任务覆盖、分歧、证据与成本状态，不生成冠军。即使已有少量读出，也只描述对应队列与版本上的结果，不宣称某模型“最懂临床”或已经建立临床预测有效性。模型概率未经前瞻校准时继续保留该说明。

## 7. 活动怎样进行，用户怎样参与

活动先用公开页面展示一个可追溯的研究流程，再随真实读出持续更新。启动演示建议为 75 分钟：

| 时间 | 内容 | 用户可以核对什么 |
| --- | --- | --- |
| 0–10 分钟 | 说明预测问题、当前 pilot 范围与结果状态 | 这是哪项试验、预测哪个终点 |
| 10–25 分钟 | 展示冻结证据，让观众先自行判断 | 哪些是事实、哪些仍是假设 |
| 25–45 分钟 | 对比已有真实模型输出与拒答 | 同一信息下的分歧、引用和未知 |
| 45–60 分钟 | 查阅专利和配对条件 | 专利是否审核、是否真的进入输入 |
| 60–70 分钟 | 展示锁定记录和未来裁定流程 | 内容指纹、时间凭证、完整失败分母 |
| 70–75 分钟 | 演示如何查阅和下载资料 | 后续怎样独立复查 |

没有真实专利配对时，演示来源与审核缺口，不替换为虚构增益曲线；没有未来结果时，演示裁定规则，不提前宣布命中。活动时间、后续更新周期和参与方式在正式发布时另行公布；本文件不表示活动已经举行或已经配置持续监控。

用户目前可浏览 `/arena`、查看具体目标与证据、按比较轨道读取结果，并下载公开记录。研发团队可据此提出单资产的研究问题，通过现有“提交试验”入口整理资料；公开访问不触发付费模型调用。团队试点的交付是有来源、可复查的研究报告，不是临床试验成功保证或患者治疗建议。

后续改进以已经裁定的错误为输入：先分析证据缺口与工作流问题，再离线评估候选版本，并在新的任务批次中登记使用。旧版本、失败和错误判断持续保留，不用新版本重写旧战绩。

---

**公开传播口径**：我们正在比较明确临床研发任务下的模型判断，并公开等待未来结果验证。可以说“真实调用已留下可追溯记录”，前提是存在相应记录；不能将接口测试、旧档案回放、候选数量、专利下载或页面上线表述为已经验证的临床预测能力。
