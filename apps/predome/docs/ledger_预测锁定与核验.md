# 预测锁定与独立核验账本

实现文件：`emeris_live/platform_store.py`、`emeris_live/platform_api.py`。本版复用既有加密 Store 与 SQLite，不搬迁账户资料。

## 数据实体和不可覆盖性

采用 `platform_` 前缀建立 trials、trial_versions、model_versions、prediction_runs、prediction_evidence、prediction_snapshots、actual_outcomes、outcome_verifications、evaluation_results、readout_events。内容使用既有 Fernet 加密；预测、来源、模型与结果记录通过 ID 关联。预测输入、输出和证据在同一规范化 JSON 内生成 SHA-256。

所有上述表都设 UPDATE/DELETE 拒绝触发器。锁定是新建快照而非改写草稿；同一草稿重复锁定返回同一记录。新模型或新输入须创建新的 run，记录 parent_prediction_id；旧快照不修改。每个账号的快照记录前一条快照哈希。查看记录时重新核对内容哈希。

这证明应用内完整性和版本关系，不构成外部公证、区块链或独立可信时间戳。服务器管理权限仍能够改变数据库与代码；此事实在输出中明确标记。

## 权限与公开边界

默认所有新预测、原始方案及输入均属于创建账号，仅可在登录后访问。锁定不自动公开。用户必须通过 `publish=true` 加 `confirm_public=true` 明确确认公开摘要。

公开视图只返回确认的试验标识、目标、模型概率、时间、公开来源 URL 和输入摘要哈希。不会返回上传方案全文、任意输入字段或可能复述私有资料的 LLM 理由。完整快照仅对本人及已配置核验人员可见。公开 SHA 是完整私有快照的 SHA，公开脱敏摘要不可据此独立重建全文；接口明确标记这一边界。

`EMERIS_REVIEWERS` 配置逗号分隔的既有账号名称。未配置时审核权限保持关闭；普通用户不能自行提升角色。结果审核者必须与预测所有者、结果提交者均不同。

## 创建与锁定条件

草稿必须记录输入、模型/流水线版本、数据截止、生成时间、严格事件定义和来源。来源日期晚于截止、截止晚于生成或已知训练截止晚于生成均拒绝。训练截止未知保持 null，禁止虚构。

模型概率仅允许有限 0–1 数值；拒答、失败、不可用必须为空。全模型不可用或仅运行条件统计情景的报告可作为草稿保存，不能伪装成正式临床预测锁定。正式锁定要求 endpoint、population、comparison、success_definition 完整，且至少一个真实模型输出可用。

HTTP 手动保存的概率固定标注 `user_submitted`，不能伪装为服务端提供商输出，也不能计入正式前瞻表现。

## 实际结果与审核队列

实际结果包括 trial_id、endpoint、population、comparison、label（0/1/未知）、readout_date、source（HTTPS URL 和发布日期）、可选效应量/区间/p 值，以及 extraction_status、conflicts。缺失、抽取失败、终点不匹配或来源冲突都保留待核验，不能因缺少阳性公告而判阴性。

审核通过要求：确切目标一致、原始公开来源、日期合法、确定的二元结果、抽取完整、无未解决冲突。独立审核人员还必须明确确认：

- endpoint_match：主要终点一致。
- population_match：预定义人群一致。
- comparison_match：治疗与对照一致。
- source_checked：核查原始结果来源。
- prespecified_analysis：确认预设主要分析及多重性规则。
- earliest_result_checked：核查首次公开目标结果日期，不能用后发表论文日期掩盖已有读出。
- evidence_cutoff_checked：检查预测证据实际可用日期与截止关系。

通过或拒绝的最终审核不可覆盖；需要纠正时应提交新的结果记录。已有获准结果时其他冲突结果不能自动替换，必须进入进一步裁定。本版没有提供抹除已审核结果的操作。

## 前瞻评价边界

公开表现只使用用户明确公开、经独立审核通过、严格锁定于首次公开读出之前、来源可用日期完整且早于截止的真实模型记录。结果与锁定同日但没有精确读出时间时，按读出日 00:00 UTC 保守判断，不能认定当日较晚的锁定为事前。

同一试验、完全相同目标、同一模型只用最早公开锁定版本作为主评价；选择发生于所有锁定记录，而不是仅从被批准的结果中选择，防止择优版本。后续版本保留但不重复计数。

概率为零是有效概率，不等于拒答；不提供任何不存在的基线概率。私有预测可以在账号内核验，但不计公开表现。历史回放、结果后锁定、证据日期不明和用户手填估计均不计前瞻表现。临床校准和外部验证仍需真实积累，不能靠账本功能本身宣称实现。

## 核验情况

单元与接口测试覆盖加密、跨账号隔离、锁定幂等/不可覆盖、脱敏公开、新版本保留、截止泄漏、非法概率、统计情景拒绝锁定、独立审核、缺失/冲突/不匹配、结果后锁定、缺失证据日期、私有绩效排除、篡改检测、权限及后版本择优排除。实际测试结果以最新 pytest 输出为准。

## 既有公开冻结档案迁移

`import_legacy_archive(store)` 是显式离线迁移入口，不通过 HTTP 接受任意路径或回填日期。迁移首先执行 `read_continuous()` 对原研究版本的全部清单文件进行哈希核验，再核对嵌入式前瞻记录与原始 `frozen_forecasts_v1.json` 完全一致，以及所保留 R2 预测与原始模型返回、独立审查记录一致。

迁移创建 10 个确定性 ID 的目标快照，每个保留两个模型的输出，包括 18 个概率和 2 个拒答。所有来源文件只读。原冻结日期、证据截止、各模型实际完成日期及模型/提示词/请求哈希分别保留。数据库适配封装的 `imported_at` 单列，标记 `provenance=archived_record_import`，不充当新的预测生成或锁定时间。

原档案记录 SHA、文件 SHA、上层发布 SHA 与新适配封装 SHA 分开保存，不把封装 SHA 当成原预测 SHA。重复迁移返回原快照和原迁移时间，不产生新的预测版本。

旧档案没有独立结构化指定分析人群/比较字段时，适配器绑定原始 target_definition、完整登记入排标准及登记治疗臂的规范化原值；不推断 ITT/PP、不编造剂量配对。审核结果时仍需确认真实来源、预设主要分析、精确目标匹配以及首次结果日期。

迁移后的公开目标可以由结果采集流程按 snapshot_id 关联到待审核记录，独立审核批准后由同一评价出口纳入符合条件的前瞻评分。没有真实结果时仍为零已核验。`public_outcome_records()` 只公开已批准且属于公开快照的结果摘要，包含实际结果日期、效应量/区间/p 值（如已提供）、来源以及模型评价状态，不返回私有审核备注。


## 列表分页与内存边界

HTTP 的 predictions、snapshots、outcomes、reviews、evaluations、public-outcomes 列表保留 records 数组，默认每页 20 条，limit 最多 100；offset 从零开始。pagination 返回 limit、offset、has_more、next_offset。最后一页的 next_offset 为 null。账号预测列表是摘要，target.endpoint 最多 1000 字符，summary_only=true；完整私有输入和模型输出仍通过已有预测详情接口访问。公开快照及公开结果继续只返回显式公开字段。

列表在 SQL 层取 limit+1 条，以额外一条判断是否有下一页；每次只解密当前行，不再 fetchall 大密文集合。评价出口迭代完整锁定集合决定唯一主版本，随后逐条解密审核结果。内部 evaluation_rows、public_outcome_records、list_public_snapshots 无分页调用仍保持完整覆盖，避免网站分页改变科学分母或遗漏采集匹配。分页仅控制 HTTP 展示。

评价仍需扫描完整锁定集合，时间复杂度随记录数增长，完整内部结果集合仍占用摘要内存。本次修复避免全部原始上传方案及密文同时驻留，不代表无限数据量下的性能验收。大量真实记录阶段仍需单独的聚合缓存和性能测试。
