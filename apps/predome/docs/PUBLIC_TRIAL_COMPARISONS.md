# 同一试验的公开研究对照

公开页原有临床 LLM 矩阵继续作为主要比较。点击模型模块右侧 **Agent & patent comparisons** 后，同一模块内按需读取额外的实际登记记录。默认不加载这些资料，页面仍保留试验、模型、共识／实际结果三个模块。旧的 1.4 详情、JSON 和 Clinical Brief 不加入新字段，也不把额外条件纳入基线投票。

## 专利条件对照

每个登记的 `patent_ablation / with_patents` 槽位均保留一行，包括失败、尚未运行和找不到唯一控制的情况。控制只在同一目标、cohort、模型和请求版本中寻找，不借用同 NCT 的另一轮登记。比较状态区分可核对判断、不完整判断和条件不可比。

登记匹配要求模型工作流、冻结配置、Prompt 和预算上限都有明确绑定，临床 packet 内容不变，新增资料仅为专利。每臂的冻结输入哈希需要对应其 packet；预期 provider 输入分别绑定各自条件，不能要求加入专利前后的输入哈希相同。可比较的返回还须确认实际配置、输入、Prompt 和返回模型版本分别符合登记。两个缺失值不算匹配。

只有条件完整且两臂均有可用判断时，才显示分类判断是否变化。显式弃权仍是 Uncertain；操作失败不能当作反对药物，也不能与另一臂凑成完整配对。概率和 Confidence 继续为 N/A，不公开原始主观数值、概率差、Brier 或专利增益。元数据匹配不是来源认证或科学批准。

## Agent 系统记录

统一审查与开放 Agent 分开列出各自判断、模型／系统版本、记录时间和来源。只有已登记的组件模型名会进入公开投影，不公开私有审查内容、Prompt、工具轨迹、配置、token、费用或调用回执。

输入匹配和共同预算上限描述冻结资料，不证明使用了相同的实际计算量。单次预测与两阶段工作流可能使用不同数量的请求和模型组合；这些记录不能单独证明 Agent 改善判断或某个基础模型更强。未确认绑定保持未知，失败记录照常展示。额外系统不参与原临床矩阵的多数票和一致性。

## 来源、结果及版本

每条运行只展示它自己记录的引用；专利行另列增加到输入中的专利来源，这不等同于模型实际引用或独立核实了每项实验。原文链接、可验证的既有快照、已记录的页码／章节／文档版本沿用公开来源规则。缺失快照保持缺失，不下载新资料或补写旧预测。

所有记录保留精确目标和 cohort。原有下拉与日历现在也能发现仍有效的更早研究登记，明确标注其身份及时间；不按 NCT 合并不同终点、成功规则或运行版本。撤回记录保留原直链，但不会作为活跃赛程。

新接口为 `GET /api/arena/public/targets/{target_id}/comparisons`，独立版本 `predome-public-trial-comparisons-1`。返回显式允许的判断、来源、分类匹配标志和固定原因，不返回内部 packet 或绑定哈希。已验证的历史档案没有新原生对照时返回空列表，未知目标为 404，损坏原生记录拒绝读取。公开 GET 不运行模型、初始化账本或写入状态。

每条运行的个别 match 元数据继续遵循既有科学接纳与事前时间门禁；未公布、混合或未接纳结果不能获得正确／错误标记。它不构成 Agent 或专利改善证据。新增展开区不产生综合评分或排名。
