# 独立 Arena 与旧研究档案

公开 Arena 使用自身的不可覆盖登记和模型记录；旧研究档案通过额外的完整性校验投影进来。两种资料可以同时展示，独立 Arena 的读取不再要求安装旧的 735 文件证据包。

## 可运行的范围

完成 README 中 Python 3.11 依赖安装后，在 `apps/predome` 中启动：

```sh
EMERIS_DATA_DIR=/absolute/private/new-predome-state .venv/bin/python run.py
```

浏览器访问 `http://127.0.0.1:19320/arena`。启动会在指定本地状态目录建立工作台基础数据库和密钥；不要将生产目录或已有密钥提交 Git。公开 GET 不会初始化 Arena ledger、生成预测或登记审核。

- **首次运行**：公开 overview 返回 200 和空的模型／目标集合，页面显示尚无可展示赛季。不存在的试验详情、JSON 和 Clinical Brief 返回 404。
- **已有独立 Arena 记录**：经现有流程登记或导入的目标、真实模型输出和失败记录按原有公开规则展示，详情、JSON 和 Brief 使用同一投影。导入真实记录的流程见[封存记录同步](SEALED_RECORD_SYNC.md)，不需要重新运行模型。
- **只有 Git 中的赛季设计**：设计和候选目录仍然是设计资料，不能变成模型执行记录或预测。
- **旧 dashboard／完整旧研究数据**：继续需要授权恢复的原证据包，未安装时保持原有不可用状态。这一修复没有伪造旧数据，也没有将新状态目录描述为真实临床演示。

## 何时可以省略旧资料

仅当应用目录下 `predome_data`、`dashboard_data`、`trial_data` 和 `public_data` 四个旧资料根均完全不存在，才省略文件档案投影。任意一个目录、文件或符号链接，包括断开的链接，都视为安装痕迹；继续执行原有的完整加载和校验。部分安装、缺失原件或校验失败不会被捕获成“没有档案”。

数据库是另一条校验边界。即使上述四个目录均不存在，公开读取仍检查 `workbench.sqlite3` 的路径、只读连接、平台结果表的完整性、既有公开快照和结果的原始校验，以及日程审核表的完整性。发现已有公开的旧档案导入记录而原件缺失时返回不可用，不能悄悄删除这部分公开记录。初始化过但没有档案导入的完整平台表可以与独立 Arena 共存。

旧档案完整安装时保留原投影、结果绑定和逐来源校验。预测算法、原始模型结果、失败、生成时间、原始来源和评分规则均保持原样；公开详情和 Clinical Brief 的 DTO 版本也没有变化。

## 验证边界

新增 `tests/test_arena_source_only.py` 使用实际应用、临时 SQLite 和显式合成登记，验证源码空状态、已登记模型记录、公开导出、只读行为及失败路径。合成登记只用于测试，既不填充产品，也不构成新的真实预测或科学审核。干净 Git archive 的实际启动检查与含授权原件的完整回归分别记录。

本轮仅更新 GitHub 候选分支，不操作服务器后台，不打包、stage 或部署，也不调用模型。文件可用和工程测试通过不等于预测能力已验证。
